# ADR-005: SQLite para persistência

**Estado:** aceite

## Contexto

O enunciado permite persistência em SQLite ou em memória.
A equipa tem 6 pessoas e orçamento fixo. O sistema é um
protótipo funcional; não há requisitos de volume que exijam
uma base de dados distribuída.

## Decisão

Usar SQLite como base de dados única para o monólito. Cada
componente acede à mesma base de dados, mas apenas às suas
próprias tabelas (imposto por convenção e verificado por
revisão de código).

## Consequências

- **Positivas:** zero overhead de operação (sem servidor de
  base de dados), fácil de testar (base de dados em memória
  nos testes), suficiente para o volume do sistema.
- **Negativas:** não escala horizontalmente; se o sistema
  crescer para múltiplos processos com escrita concorrente
  intensa, SQLite torna-se um bottleneck.

## Alternativas rejeitadas

- **PostgreSQL:** overhead de setup e operação desnecessário
  para 6 pessoas e um protótipo.
- **Em memória apenas:** os dados não sobrevivem a um restart,
  o que impossibilita testar a US-3 (reenvio após falha de rede).
