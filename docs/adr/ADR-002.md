# ADR-002: Gateway de Docas como processo separado

**Estado:** aceite

## Contexto

As docas comunicam por rede móvel com falhas frequentes. O
contrato penaliza se mais de 10% das estações ficarem
inoperacionais por 1 hora. O Gateway de Docas é o único ponto
de contacto com o hardware e é crítico para a disponibilidade.

## Decisão

O Gateway de Docas corre como um processo Python separado do
monólito principal. Comunica com o monólito via HTTP interno.
Esta separação permite-lhe ser deployado, monitorizado e
reiniciado independentemente do resto do sistema.

## Consequências

- **Positivas:** falha no monólito principal não impede o
  Gateway de continuar a receber e guardar eventos. Pode ser
  escalado ou redeployado sem downtime do resto do sistema.
- **Negativas:** introduz comunicação de rede interna; há um
  contrato de API entre o Gateway e o monólito que tem de ser
  mantido.

## Alternativas rejeitadas

- **Gateway dentro do monólito:** uma falha no monólito
  (ex: bug num relatório) mata também a receção de eventos
  das docas, violando a disponibilidade.
