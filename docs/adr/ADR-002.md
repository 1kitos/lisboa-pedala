# ADR-002: Gateway de Docas — separação de namespace

**Estado:** aceite (decisão de produção; protótipo diverge,
ver nota abaixo)

## Contexto

As docas comunicam por rede móvel com falhas frequentes. O
contrato penaliza se mais de 10% das estações ficarem
inoperacionais por 1 hora. O Gateway de Docas é o único ponto
de contacto com o hardware e é crítico para a disponibilidade.
Uma falha no monólito (ex: bug num relatório) não pode matar
a receção de eventos das docas.

## Decisão

O Gateway de Docas vive no namespace `gateway/`, separado de
`lisboa_pedala/`. Em produção correria como processo Python
independente, podendo ser deployado e reiniciado sem downtime
do monólito.

## Nota sobre o protótipo

No protótipo, o Gateway corre no mesmo processo que o monólito
(incluído como router FastAPI em `main.py`). Esta é uma
simplificação consciente documentada em `prompts/gateway.md`.
A separação de namespace (`gateway/` vs `lisboa_pedala/`) e as
regras de allowed-to-use são mantidas mesmo no protótipo,
garantindo que a arquitectura alvo é preservada na estrutura
do código.

## Consequências

- **Positivas:** isolamento de falhas em produção; a separação
  de namespace é verificável por fitness functions mesmo no
  protótipo.
- **Negativas:** no protótipo, uma falha no monólito afecta
  também o Gateway — aceitável para o âmbito do trabalho.

## Alternativas rejeitadas

- **Gateway dentro de `lisboa_pedala/`:** mistura o ponto
  crítico de disponibilidade com o resto do domínio;
  impossível separar em produção sem refactoring.
